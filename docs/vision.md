# vision.md — 项目愿景与战略定位

> 这份文件是什么：modes 智能编排器的战略总纲——我们是谁、做什么、不做什么、凭什么赢。
> 什么时候该读：每个开发 session 开始前；任何"要不要做这个功能"的争论，先回到这里对答案。
> 日期：2026-09-12

---

## 1. 战略四层栈

```
品牌    modes —— 伞品牌，第一天启用（零成本，与代码基底解耦）
旗舰    智能编排器（本仓库，全部开发带宽）
衍生品  modes 工作台 —— 进 backlog，等旗舰验证后再启动
封存    modes 旧仓其余资产 —— 归档不管，只修致命 bug
```

品牌伞从第一天挂上，但衍生产品严格排队。参照 hermes → Nous Portal 的路径：先有旗舰的用户量，后有衍生平台；顺序反了就是个人开发者的头号死法（产品线摊太早）。

## 2. 产品定义

**modes 智能编排器 = fork AionUi v2.2.2（产品壳 + 国产生态）+ 移植 Orca 编排协议（任务 DAG + worker 契约）+ hermes 记忆思想（路由器长期记忆）。**

市场空位（源码级调研结论，详见 docs/research.md）：

- Orca：把"怎么协作"做成了严肃协议，但刻意不提供编排智能（大脑是外置的 agent）。
- AionUi：提供了内置引擎和易用性，但协作停留在 Leader 群聊水平，没有 DAG、没有契约。
- **中间的空位——"有协议的智能编排"——无人占据。这是我们的位置。**

## 3. 合规三档线（只做绿的）

| 档位 | 行为 | 决策 |
|---|---|---|
| 🟢 绿 | 官方非交互模式（claude -p / codex exec / gemini -p / qwen -p）；跨厂商切换；做工具让用户编排自己的 CLI（BYO） | **只做这些** |
| 🟡 灰 | 订阅账号 7×24 跑自动化流水线（厂商以限速应对，产品在和对赌限速器） | 不做卖点，不主动支持 |
| 🔴 红 | 同厂商多账号池轮换突破限额；转售/代跑；反向代理他人请求 | 永不触碰 |

**BYO 三原则：**

1. 用户自带订阅 / API Key，产品不经手额度；
2. 额度策略用"冷却"而非"硬闯"——这家用完切别家，不是这家撞墙再挤；
3. 永远不碰账号共享与转售。

守住这三条，合规风险与 Orca、AionUi 同级——即几乎没有。

## 4. 差异化：只押"编排智能"

远程访问、IM 通知（Telegram/飞书/Slack）、统一 GUI——AionUi 已经占了，做这些不是差异化，是跟跑。

我们唯一的差异化轴心是**编排智能**：额度感知路由、任务×模型匹配、fan-out 交叉评审、以及由 JSONL 效果数据驱动的、越用越准的路由长期记忆。

## 5. 非目标（明确不做）

1. **不为裸 API 自建 agent loop。** 端点层只接"会说 ACP 或有官方非交互模式的 CLI"；agent loop 是 substrate，该买不该造。
2. **不追 Orca 的打磨度和完整性。** 它有 YC 团队和每日发版，我们赢差异点，不赢 completeness。
3. **衍生品在旗舰验证前不动。** modes 工作台在 backlog 里排队。
4. **作品平台封存。** 见 §8。
5. **不做账号池、额度转售、中转代理。** 见 §3 红线。

## 6. Dogfooding 成熟度硬指标

"产品成不成熟"用数据说话，不用感觉：

| 里程碑 | 硬指标 |
|---|---|
| v0.3 | 自家 20% 的新功能用它自己的编排流程开发 |
| v0.5 | 记录每次真实任务的端到端耗时 vs 单模型基线，用数据证明提效。评测集用 harness 仓库的 `evals/coding-parity` 中英双语编码任务数据集 |
| v1.0 | 连续一周，自己的日常编码全部走自家产品；出了问题修产品，不绕开它 |

过不了这三关，就不叫成熟产品。

**第 30 天 kill criteria**：第 30 天盘点——如果自己还没有每天在用这个产品，停下来复盘定位，而不是堆功能。

## 8. 长期愿景（封存）

**作品平台**：与"使用产品产生的成果"相关的平台，绝不仅是展示。当前判断：价值在**成果血缘记录与可复现性**（每个作品带着它被哪个编排流程、哪些模型、几轮迭代做出来的完整记录），纯展示没有壁垒。
